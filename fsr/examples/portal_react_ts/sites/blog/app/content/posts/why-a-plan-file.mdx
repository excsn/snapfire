A loader is lowered to a form the host runs itself, so nothing on the serving path evaluates JavaScript. The plan file is the whole description of a route: its pattern, its loader, its layout and what each one reads.

That is why a page whose loader reads nothing from the request can be written to disk once. The host can tell from the plan, without running anything.

## What a loader becomes

The loader below reads the route's parameter and nothing else, so its body is a row of the plan rather than code the server runs:

```ts title="routes/post/[slug]/page.loader.ts" {2}
export async function load({ params }: Ctx<"/post/{slug}">) {
  return { slug: params.slug };
}
```

## Who reads which part

| Part of the plan | Read by |
| --- | --- |
| The pattern | the router |
| The loader | the host, in Rust[^rust] |
| The layout | the renderer |
